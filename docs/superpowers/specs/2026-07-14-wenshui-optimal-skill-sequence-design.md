# 问水诀最优技能序列设计

## 目标

根据用户输入的 `1-600` 秒战斗时长，在当前装备、奇穴、秘籍、团队增益、加速和网络延迟配置下，搜索当前计算预算内期望 DPS 最高的问水诀技能执行策略。

结果包含主技能序列和随机触发技能的条件规则。用户可以将结果一键应用为当前自定义循环，并继续使用现有 DPS 计算、技能统计和方案保存能力。

## 已确认约束

- 首版仅支持问水诀。
- 搜索最长运行 `60` 秒，目标是使用 `30-60` 秒进行深度搜索。
- 有限战斗时长范围为 `1-600` 秒，不支持 `∞`。
- 起手状态固定为轻剑姿态、`0` 点剑气、无职业起手 Buff。
- 搜索结果允许包含条件动作，例如“断潮可用时优先释放”。
- 搜索完成后支持一键应用为当前自定义循环。
- 长时长结果表述为“当前预算内找到的最高期望 DPS 序列”，不宣称数学意义上的全局最优。

## 现状与限制

现有 `src/计算模块/dps-kernel-optimizer` 使用 BFGS-B 优化会心、破防和破招的属性分配，不处理技能顺序。

现有 `循环秒伤计算` 接收聚合后的 `循环技能详情[]`，可以计算不同技能和增益组合的总伤害，但不能表达技能 CD、剑气、姿态和 Buff 时间轴。

仓库内已有多个心法循环模拟器框架，但公共版只加载问水诀，问水诀当前没有循环模拟器。新功能需要先建立问水诀状态模拟，再在该状态机上执行搜索。

## 方案选择

采用 Beam Search 与分支限界组合算法。

没有选择纯贪心算法，因为它容易牺牲后续高价值 Buff、剑气窗口和长 CD 技能。没有选择遗传算法或蒙特卡洛树搜索作为主算法，因为两者在固定计算预算下更难保证确定性和可验证性。

Beam Search 允许保留多个姿态、剑气区间和关键 Buff 状态；分支限界、等价状态去重和乐观伤害上界可以显著减少无效分支。短时长场景通过穷举验证，长时长场景使用现有 Excel 循环作为最低基线。

## 系统架构

### 问水诀状态模拟器

状态模拟器使用纯 TypeScript 实现，不依赖 React、Redux 或浏览器 API。

状态至少包含：

- 当前郭氏帧和目标结束帧
- 当前轻剑或重剑姿态
- 当前剑气
- 公共 GCD、自身 GCD 和技能 CD
- 当前读条及待生效事件
- 当前自身 Buff、目标 Buff、层数和过期时间
- 断潮等随机触发技能的可观察可用状态
- 当前随机分支的到达概率
- 当前技能释放记录和累计伤害事件

模拟器对外提供以下能力：

- 创建固定起手状态
- 枚举当前合法动作
- 执行单个动作并返回新状态
- 推进到下一个 CD、GCD、读条或 Buff 事件
- 返回动作是否可执行及失败原因
- 导出有序技能记录、条件规则和伤害事件

模拟器必须保持不可变输入语义。搜索节点可以共享未变更数据，避免完整深拷贝大型对象。

### 时间与事件口径

问水诀模拟器复用现有循环模拟器的时间语义，不建立另一套小数秒规则：

- 每秒使用 `16` 个郭氏帧。
- 用户输入限制为 `1-600` 的整数秒，目标结束帧为 `战斗时长 * 16`。
- 技能 GCD、读条和倒读条使用现有 `获取实际帧数`、`获取倒读条实际帧数分布` 等加速取整工具。
- 当前加速值使用主页面已经计算出的装备加速与启用增益加速之和。
- 网络延迟沿用现有循环模拟器的等待语义和单位转换，不在问水诀搜索器内重新定义。
- 同一帧事件使用稳定优先级：先结算到时的读条、DOT、触发和 Buff 事件，再执行该帧允许开始的玩家动作，最后进行 Buff 过期清理。
- 技能开始释放、读条完成和伤害命中分别记录时间；只有命中帧 `<=` 目标结束帧的伤害计入总伤。
- 在结束帧前开始但结束帧后命中的技能可以保留在执行日志中，但其越界伤害为零，搜索上界和剪枝必须按此处理。

上述规则需要以现有通用模拟框架测试为参照，并为问水诀补充同帧事件和结束边界回归测试。

### 期望伤害评估器

主线程在启动 Worker 前，从当前 Redux 方案生成只读计算快照：

- 装备信息
- 奇穴与秘籍
- 增益开关和团队增益轴
- 加速与网络延迟
- 当前目标
- 武器类型和装备特效

评估器复用现有技能系数、技能增益和 DPS 计算规则，生成不同技能与职业 Buff 组合的单次期望伤害表。

与技能顺序无关的固定装备伤害或平均覆盖增益不参与搜索分支排序，只在候选最终复算时加入。会受技能时点或快照影响的数据必须进入模拟器状态或伤害事件标签。

### 序列搜索器

搜索器运行在 Web Worker 中，避免阻塞页面。

每个节点包含：

- 压缩后的模拟状态
- 主技能序列
- 条件动作集合
- 当前随机分支的到达概率和累计伤害
- 同一策略下尚未结束的概率加权状态集合
- 剩余时间乐观伤害上界
- 用于确定性排序的稳定序号

每轮搜索执行：

1. 枚举当前合法技能、姿态切换、条件技能和必要等待动作。
2. 执行动作并生成下一状态；遇到会心触发等随机事件时，按概率拆分为可观察的成功与失败状态。
3. 淘汰超过战斗结束时间或无法继续执行的非法状态。
4. 仅合并玩家可观察信息和后续决策完全一致的等价状态，并保留正确的概率权重。
5. 使用概率加权累计伤害与乐观伤害上界，淘汰不可能超过当前最佳结果的策略分支。
6. 按姿态、剑气区间和关键 Buff 状态分组保留候选，避免搜索过早收敛。
7. 周期性回传当前最佳结果、耗时和搜索统计。

搜索使用固定种子和稳定排序。同一输入必须产生相同结果。

搜索种子包括：

- 从 Excel 技能时间轴提取并固化的合法有序基线；现有 JSON 只有聚合数量，不能直接当作技能序列种子
- 基于技能优先级生成的合法贪心候选
- 必要时由短轴模板重复生成的候选

用户取消、达到 `60` 秒或搜索空间收敛时，Worker 返回当前最佳合法结果。

### 条件执行策略

会心触发类技能不能被可靠地放入完全固定的技能数组。结果使用“主序列 + 条件插入规则”表达，并将整个结果视为基于可观察状态决策的策略，而不是单条确定性路径。

条件规则至少包含：

- 触发技能名称
- 触发条件
- 优先级
- 可插入的时间或主序列位置范围
- 条件不满足时的回退行为

首版条件规则主要用于断潮。搜索时根据当前面板会心率拆分触发成功和失败分支；后续动作可以根据玩家实际可见的断潮可用状态不同而变化。策略总伤是所有终止分支按到达概率加权后的期望值。

## 问水诀规则范围

首版包含：

- 轻剑阶段剑气获取技能
- 轻重剑姿态切换
- 夕照雷峰、云飞玉皇、鹤归孤山、风来吴山等当前循环输出技能
- 九皋鹤野、玉山揽云、破招和神兵等派生伤害
- 断潮等会心触发技能
- 造化、雾锁、层云、怜光等当前奇穴伤害状态
- 技能 CD、GCD、读条、加速和网络延迟
- 当前紫武或大橙武限制
- 当前团队增益轴与快照配置

首版不包含：

- 不影响木桩伤害的位移、减伤和控制技能
- 目标移动、转火、无敌阶段和多目标场景
- 主动打断读条和走位损失
- 自动攻击，除非 Excel 或现有伤害数据明确计入当前问水诀 DPS

规则数据源优先级：

1. 当前项目已有测试和技能系数
2. 仓库内 Excel 技能轴与公式
3. 奇穴和秘籍定义
4. 缺少权威依据的规则标记为未建模，不自行猜测

## 结果转换与精确复算

搜索结果先转换为有序技能记录和条件规则，再将所有随机终止分支按到达概率聚合，按“技能名称 + 技能增益签名”生成允许小数数量的 `循环技能详情[]`。

最终候选必须通过现有 DPS 内核精确复算。搜索器可以使用增量期望伤害进行大规模剪枝，但最终排序以概率加权技能数量经过现有 DPS 内核计算后的结果为准。

现有 Excel 循环基线只有在以下条件同时满足时才参与比较：

- 已从 Excel 技能时间轴提取出相同奇穴和武器条件下的合法有序基线
- 能在相同装备、增益、秘籍和目标战斗时长下复算

不能满足同口径比较时，不使用聚合数量直接冒充有序基线。此时以合法贪心序列作为最低搜索基线，并在结果中标记没有可比 Excel 基线。

转换结果包含：

- `战斗时间`
- `技能序列`
- `条件规则`
- 聚合后的 `技能详情`
- 预期总伤和 DPS
- 搜索耗时和搜索统计

需要扩展循环类型，使自定义循环可以持久化条件规则和优化元数据。现有循环消费方忽略未知可选字段时必须保持兼容。

## 页面交互

入口放在基础设置的循环模拟位置，将问水诀当前禁用的“循环模拟”按钮替换为“最优序列”。

弹窗包含：

- `1-600` 秒战斗时长输入
- 开始和停止搜索命令
- 已用时间、时间预算进度、当前最佳 DPS 和相对当前循环提升
- “技能序列”和“技能统计”两个结果页签
- 应用为当前循环命令

运行期间页面保持可操作。搜索结果保存在弹窗局部状态，应用前不修改 Redux 当前方案。

用户主动停止时保留已找到的最佳合法结果。Worker 异常、数据不完整或未找到合法结果时，不修改当前方案。

应用结果时创建名称形如 `最优序列-220s` 的自定义循环，写入技能序列、条件规则、聚合技能详情和目标战斗时长，然后切换到该循环并只触发一次正式 DPS 计算。

## 错误处理

- 非有限数值、低于 `1` 或高于 `600` 的时长不允许启动。
- 缺少装备基础攻击、技能数据或必要配置时返回数据错误。
- Worker 消息必须带任务 ID，忽略已取消或过期任务的结果。
- 发送给 Worker 的计算快照必须是可结构化克隆的纯数据 DTO，不传递 Map、函数、React 对象或 Redux 引用。
- Worker 异常时终止任务并保留当前方案。
- 搜索结果应用前再次校验心法和配置指纹，避免用户在搜索期间修改方案后应用过期结果。
- 最终精确复算失败时不允许应用。

## 测试与验收

### 模拟器单元测试

- 轻剑、0 剑气、无职业 Buff 的固定起手状态
- 剑气获取、消耗和上限
- 姿态、CD、GCD、读条和网络延迟限制
- 造化、雾锁、层云等 Buff 的产生、消耗和过期
- 战斗结束时间后的技能命中不计入结果

### 搜索算法测试

- `1-10` 秒场景通过穷举所有随机结果和可观察状态决策，与最优期望策略一致
- 相同输入结果确定
- 概率分支和等价状态合并后保持总概率与期望伤害正确
- 条件技能生成合法规则
- 取消和超时返回当前最佳合法结果
- 有同口径有序 Excel 基线时结果不低于该基线；否则不做不成立的 Excel 基线比较

### 转换和集成测试

- 有序技能记录正确聚合为 `循环技能详情[]`
- 聚合结果与模拟器伤害事件一致
- 自定义循环保留技能序列、条件规则和战斗时长
- 应用前不修改方案，应用后只触发一次正式 DPS 计算

### 页面和性能验收

- 输入严格限制为 `1-600`
- Worker 运行期间页面可操作
- 停止搜索后保留最佳结果
- 实际执行一次 `600` 秒搜索，在 `60` 秒内结束并返回合法序列
- 运行问水诀现有 DPS 回归测试和项目构建

## 完成标准

- 用户可以输入任意 `1-600` 秒战斗时长并启动搜索。
- 搜索期间页面不阻塞，可查看进度并取消。
- 搜索返回主序列、条件规则、期望 DPS 和技能统计。
- 短时长结果通过穷举最优验证。
- 长时长结果不低于适用的现有 Excel 基线。
- 用户可以将结果应用为当前自定义循环。
- 当前问水诀 DPS 测试、相关新增测试和构建验证通过。
