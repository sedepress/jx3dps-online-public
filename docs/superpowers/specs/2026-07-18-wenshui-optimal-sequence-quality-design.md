# 问水诀最优序列质量修复设计

## 背景

当前问水诀“最优序列”在默认配装、220 秒场景下，完整管线得到的正式复算结果为 `4,781,540 DPS`，而当前预设循环为 `5,534,477.43 DPS`，搜索结果低 `13.6045%`。

现有实现存在三个相互关联的问题：

- Worker 只返回近似模型中的单个最高分候选，正式 DPS 计算没有参与候选间排序。
- 当前预设循环没有作为搜索结果候选参与最终精确重排，只在页面结果转换阶段以空序列形式兜底。
- 完整管线性能测试只校验差值为有限数，没有校验正式复算结果不得低于预设循环。

技能序列结果目前只显示文字，没有技能图标；预设循环 JSON 也没有可供兜底结果展示的 `技能序列`。

## 目标

- 最终展示和可应用的结果，必须按项目正式 DPS 计算器复算并排序。
- 最终结果的正式 DPS 不得低于同配置、同战斗时间的当前预设循环。
- 搜索结果必须包含完整的玩家按键序列，并为每个动作展示技能图标。
- 搜索未找到更高结果时，明确展示预设循环为当前最高结果，而不是展示低 DPS 搜索结果或空序列。
- 短时长继续通过穷举 oracle 验证数学最优；长时长明确表述为“当前搜索预算内，经正式复算后的最高序列”。

## 非目标

- 不在本次改动中宣称 220–600 秒组合搜索达到数学意义上的全局最优。
- 不把断潮、破招、九皋鹤野·落剑、四季剑法等自动触发伤害混入玩家按键主序列。
- 不重做通用循环模拟器 UI，也不改动其他心法的搜索逻辑。
- 不改变问水诀现有预设循环本身的伤害口径。

## 方案比较

### 方案一：仅保留页面兜底

继续让搜索器返回低分候选，页面发现正式 DPS 较低后展示当前循环。

优点是改动最小。缺点是没有找到更好的序列、兜底没有按键序列、搜索进度和结果含义不真实。该方案不能满足目标。

### 方案二：只修近似模拟器

逐项修正技能规则，使近似模型尽量贴近预设循环，然后仍返回单个候选。

优点是提升搜索评分质量。缺点是近似模型和正式 DPS 计算器仍是两个口径，未来装备、增益或技能规则变化后仍可能再次选出正式 DPS 更低的候选。

### 方案三：预设基线参与最终竞争，多候选正式复算

将预设循环作为正式候选；Worker 返回一组多样化高分候选；主线程把搜索候选和预设候选统一交给正式 DPS 计算器复算，按正式 DPS 选出胜者。同时修复已确认的模拟数量偏差，提高候选池质量。

该方案同时提供质量下界和继续搜索提升的能力，是本次采用的方案。

## 总体架构

搜索分为四个阶段：

1. **构造预设基线**：匹配当前装备、奇穴、秘籍、加速、延迟和战斗时间对应的循环详情，取得正式技能详情和正式 DPS；使用现有 Excel 动作 token 执行器生成同战斗时间的合法玩家按键序列。
2. **Worker 近似搜索**：Beam Search 继续使用轻量伤害表快速扩展，但保留最多 16 个状态多样、近似分高的完整候选，而不是只返回一个候选。
3. **主线程正式复算**：聚合每个搜索候选的技能详情，把它们与预设基线候选一起使用项目正式 DPS 入口复算；按正式 DPS、近似总伤、稳定序号依次排序。
4. **展示和应用胜者**：展示正式复算后的第一名。第一名为预设时标记“预设基线”；第一名为搜索结果时标记“搜索提升”，并允许应用为自定义循环。

最终选择不依赖 Worker 的单个近似最高分，因此正式 DPS 下界由候选集合中的预设基线保证。

## 数据结构

新增统一候选结构，至少包含：

```ts
interface 问水可复算候选 {
  id: string
  来源: '预设基线' | 'Beam搜索'
  技能序列: string[]
  条件规则: 问水搜索条件规则[]
  技能详情: 循环技能详情[]
  近似期望伤害: number
  稳定序号: number
}
```

Worker 结果增加 `候选列表`。为兼容现有进度展示，仍保留 `最佳候选`，其值等于候选列表中近似伤害最高的一项。

展示结果增加：

```ts
interface 问水技能序列展示项 {
  序号: number
  技能名称: string
  图标: string
  开始帧?: number
  开始秒?: number
}

interface 问水优化展示结果 {
  结果来源: '预设基线' | 'Beam搜索'
  候选数量: number
  当前循环DPS: number
  DPS提升: number
  技能序列展示: 问水技能序列展示项[]
}
```

## 预设基线序列

预设循环的正式 DPS 和技能详情继续来自当前循环详情，不能从搜索模拟器反推。

玩家按键序列来自当前已生成的 Excel 斩岳或碧归动作 token：

- `叠1-鹤归孤山` 展开为 `莺鸣柳 → 鹤归孤山`。
- `云飞玉皇-峰插` 展开为 `云飞玉皇 → 峰插云景`。
- `听雷-轻` 展开为 `啸日 → 听雷-轻 → 啸日`。
- 其他复合 token 继续复用 `解析问水Excel动作Token`。

序列在模拟器中执行到当前战斗时长，返回实际成功执行的动作记录。它只用于展示、应用和搜索种子；预设基线正式 DPS 仍使用预设技能详情计算。

如果当前配置没有可用 Excel token 基线，则使用当前自定义循环已有的 `技能序列`。两者都不存在时，任务创建失败并提示“当前循环缺少可搜索的玩家按键序列”，不得生成空序列结果。

## 候选池与精确重排

Beam Search 在每一层继续按状态去重，但额外维护一个有界候选池：

- 候选必须已经推进到战斗结束帧，或不存在可继续产生伤害的合法动作。
- 按近似期望伤害降序保留候选。
- 相同状态键只保留更高伤害候选。
- 最终最多返回 16 个候选。
- 候选池不足时，用当前 Beam 最佳候选补足，但不得重复。

主线程转换每个候选并调用正式 `秒伤计算`。正式重排必须始终包含预设基线，且不受 Worker 候选数量限制影响。

排序规则：

1. 正式 DPS 更高者优先。
2. 正式 DPS 在浮点容差内相同时，近似期望伤害更高者优先。
3. 再相同时，玩家按键更少者优先。
4. 最后按稳定序号保证结果可复现。

## 模拟器数量对齐

正式基线保证结果下界，但搜索器仍需修复当前已观测到的候选质量问题。默认配装 220 秒诊断数据中：

- `九皋鹤野·落剑`：搜索 `44`，预设 `74`。
- `鹤归孤山`：搜索 `11`，预设 `15`。
- `四季剑法`：搜索 `84`，预设 `92`。
- 搜索结果缺少预设的轻剑起手段。

实现时以“同一玩家按键序列在模拟器聚合后的主动及衍生技能数量”为回归对象，逐项检查：

- Excel token 展开和轻重剑切换。
- 莺鸣柳、啸日充能恢复及叠锋意缩减。
- 鹤归孤山触发的山倾、九皋落剑和四季剑法。
- 夕照、云飞的九皋层数消费与云飞 CD 缩减。
- 结束帧前释放、结束帧后命中的计入边界。

装备特效和按战斗时间追加的公共技能不进入动作模拟器，由正式 DPS 复算统一追加。

## 技能图标与序列 UI

新增问水诀主动技能展示映射，覆盖搜索动作空间中的全部玩家动作：

- 莺鸣柳
- 啸日
- 听雷-轻
- 黄龙吐翠
- 平湖断月
- 九溪弥烟-轻
- 夕照雷峰
- 云飞玉皇
- 云景·云飞玉皇
- 鹤归孤山
- 风来吴山
- 峰插云景

图标使用 JX3BOX 稳定技能图标地址并集中维护；技能变体复用对应基础技能图标。映射缺失时显示心法图标作为视觉兜底，同时测试必须保证当前动作空间没有缺失映射。

“技能序列”标签改为可滚动图标流：

- 每项显示顺序编号、32px 技能图标和技能名称。
- 桌面端按自然流式换行，移动端保持单列或双列可读。
- 鼠标悬停显示完整技能名；图片使用技能名作为 `alt`。
- 自动触发技能不插入主序列，继续在“技能统计”标签展示期望数量。
- 结果顶部同时显示“预设 DPS”“最高 DPS”“提升值”和结果来源。

当预设基线胜出时，仍完整展示预设按键序列和图标；应用按钮保持禁用，因为当前循环已经是胜者。搜索结果胜出时，应用按钮可用。

## 错误处理

- 预设正式 DPS 不是有限数：阻止搜索并显示明确错误。
- Worker 候选无法聚合或缺少技能系数：丢弃该候选并记录失败原因；只要仍有预设基线即可返回结果。
- 所有 Worker 候选都失败：返回预设基线，并显示“搜索候选复算失败，已保留预设基线”。
- 技能图标加载失败：浏览器使用心法图标兜底，不影响搜索和应用。
- 配置指纹或战斗时间变化：沿用现有过期保护，禁止应用旧结果。

## 测试与验收

### 搜索质量

- 默认配装 220 秒完整管线必须断言最终正式 DPS `>=` 当前预设循环正式 DPS。
- 完整管线必须断言最终技能序列非空，并且胜者候选包含正式复算数据。
- Worker 必须返回不超过 16 个、无重复 ID 的候选。
- 短时长测试中，候选池正式重排结果必须与穷举 oracle 的最优结果一致。
- 相同输入重复运行必须返回相同胜者和相同玩家按键序列。

### 模拟规则

- Excel 基线在 220 秒下可生成合法的非空玩家按键序列。
- 对固定动作前缀分别断言轻剑切换、九皋落剑、四季剑法和鹤归数量。
- 搜索候选和预设技能数量差异输出为诊断信息，关键主动/衍生技能不允许出现已确认的系统性漏算。

### UI

- 技能序列逐项渲染图片、序号和技能名。
- 所有搜索动作都有非空图标映射。
- 预设胜出时展示“预设基线”且禁止应用。
- 搜索胜出时展示正式 DPS 提升并允许应用。
- 配置变化后继续禁止应用。

### 完成验证

- 运行问水诀最优序列目录的全部 Jest 测试。
- 运行 `src/心法模块/心法/问水诀/问水诀dps.test.ts`。
- 启用 220 秒完整管线基准并确认正式 DPS 不低于预设。
- 运行项目生产构建。
- 完成代码审查和 completion verification。

## 完成标准

- 用户能够看到带技能图标的完整玩家按键序列。
- 页面展示的最高 DPS 来自正式 DPS 复算，而不是 Worker 近似分数。
- 默认配装 220 秒结果不低于 `5,534,477.43 DPS` 的当前预设基线。
- 搜索没有提升时，预设基线以完整序列形式成为胜者。
- 搜索有提升时，可应用胜者并得到与弹窗一致的正式 DPS。
- 相关测试、真实基准和生产构建均通过。
